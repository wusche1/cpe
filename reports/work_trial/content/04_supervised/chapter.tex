The big advantage of CPE is that it is an unsupervised method.
It can surface behaviour that we did not previously know we should be looking for.
But in many of the scenarios where it was demonstrated, we could also use more supervised methods, like CAA or SFT.
Here we investigate the difference in performance of CPE relative to similar supervised methods in some of these scenarios.

We compare CPE against CAA \citep{panickssery2024} and against SFT on the same rank-1 LoRA shape that CPE uses, with matched training time to make the comparison fair.

One restriction of these supervised methods is that they need more data to apply.
For SFT you need data of the behaviour, and for CAA you need examples of the behaviour and of its opposite.
We used two tasks: Countdown, where the model must reach a target number with arithmetic, and a sycophancy task, where the model must recall a trivia answer under planted doubt from the user.
Both have clean programmatic labels, so the supervised methods can be fed either gold labels, the dataset's own targets, or the model's own answers sorted by correctness, as in STaR \citep{zelikman2022}.
Table~\ref{tab:indomain} compares them.

\subsection{Does CPE generalize better than supervised methods?}

While supervised methods beat CPE at the specific thing they are optimized for, one might hope that CPE generalizes better out of that distribution.
To test this, we trained password-locked models that sandbag on two different capabilities: multiple-choice question answering and MBPP coding problems \citep{austin2021}.
Both arms of the lock are imitation: with the password the organism reproduces its own answers, and without it the answers of a much smaller model.
The unlocked ceiling is therefore the base model by construction, and the whole gap is suppressed ability rather than newly taught skill.
The top of Table~\ref{tab:transfer} gives what each organism hides; their training details are in Appendix~\ref{app:two-behaviour}.

We then applied CAA, SFT and CPE, but using only the data from the MCQA task, and measured how much this also improved performance on the programming task.

At first we tried this on the 14B organism, and found that CPE, and indeed none of the methods, generalized to the programming task.

We then changed the way CPE is applied.
Instead of using LoRA $A$ to contextually activate LoRA $B$, we used $B$ alone as a steering vector that is always active.
Intuitively this makes the learned behaviour, not sandbagging, active everywhere rather than only in the context it was learned in.
Using $B$ as a steering vector this way leaves open the question of that vector's steering strength.
At first we used the average value of the activation times LoRA $A$ over the MCQA data, which again had no effect on the programming data.
Afterwards we swept steering strengths and used the strength with the biggest effect on the programming dataset, which led to a successful improvement there.
This methodology, however, violates the principle of not taking the effect on the programming performance into account.

So we then trained the other model organism, the 8B, to have an evaluation case, and used the same steering strength there.
This also turned out to generalize across tasks.
But then it turned out that on the 8B organism the plain CPE factor also generalized across tasks.
Table~\ref{tab:transfer} compares the methods, and Figure~\ref{fig:gen-magnitude} shows how both tasks respond to the magnitude of the ungated vector.

While SFT and CAA find slightly higher effects on the behaviour those methods are trying to elicit, CPE can elicit behaviour like sandbagging more robustly across different settings.
